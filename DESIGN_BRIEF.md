# Design Brief: Willickr - The Computational Data Loom

**To:** Creative Lead / Interactive Designer
**From:** Antigravity (AI Orchestrator) & The Operator (User)
**Subject:** Defining the Visual Language of a Generative Data Instrument

## 1. The Vision
**Willickr** is not a DAW. It is a "Data Loom"—a computational instrument where an AI agent translates raw data (images, weather patterns, math functions, text) into music in real-time.

The user doesn't drag MIDI notes. They say, *"Play this hurricane map as a techno rumble,"* and the AI spins up the algorithms to do it.

**We need your help to define the visual interface for this interaction.** We want an interface that feels like a futuristic scientific instrument, a cockpit for exploring data topologies, not a standard SaaS dashboard.

## 2. Aesthetic Direction: "Data Alchemy"
We are aiming for a **"Premium Dark Mode"** aesthetic, but we want to move beyond generic "admin panel" vibes.
*   **Keywords**: Bioluminescence, Mathematical Sublimity, The "Ghost in the Machine", Precision Engineering, Tactile Void.
*   **Atmosphere**: Think of a radar screen in a deep-sea submersible, or the HUD of a spacecraft exploring a nebula. Low light, high contrast, neon accents that signify "live" signals.

## 3. The Core Challenge: Visualizing the Invisible
We need concepts for three specific UI challenges:

### A. "The Loom" (The Main Viewport)
This is where the data lives. It isn't always a timeline.
*   **Challenge**: How do we visualize a "Terrain Walker" algorithm crawling across a 3D heightmap of a mountain range to generate pitch data?
*   **Challenge**: How do we visualize a textual analysis algorithm "chewing" through a poem to spit out drum triggers?
*   **Ask**: We need a flexible "stage" concept that can render 2D images, 3D terrains, or abstract abstract particle flows depending on the "Translation Mode" active.

### B. The "Ghost Hands" (AI Presence)
The AI is constantly tweaking parameters. We don't just want a log text saying `Configured Filter Cutoff`.
*   **Challenge**: How do we visually represent the AI's influence?
*   **Idea**: Maybe "ghost faders" that glow when the AI touches them? Connecting lines (patch cables) that draw themselves between data sources and synth params?
*   **Ask**: Concepts for how the AI's "intention" is visualized before and during execution.

### C. Ephemeral Controls (Soft-Synths for Data)
The AI can spawn controls on demand. *"I've created a chaos slider for you."*
*   **Challenge**: These UI elements appear dynamically. They shouldn't look like standard HTML inputs.
*   **Ask**: A design pattern for "grown" or "spawned" UI controls (XY pads, sliders, toggles) that feel integrated into the data stream, rather than slapped on top.

## 4. Specific Deliverables (Conceptual)
We aren't asking for final CSS, but meant-to-inspire high-fidelity mockups or sketches for:
1.  **The "Loom" State**: A mockup showing a standard session. Perhaps a satellite image is being scanned in the center, generating MIDI notes (visualized as sparks/beams) flying off towards an "Output" sector.
2.  **The "Translation" Metaphor**: A visual schema for showing: `Input Source (Image)` -> `Algorithm (Scanline)` -> `Output (MIDI Channel 1)`. How does this "pipeline" look?
3.  **Motion Behaviors**: Descriptions or sketches of how things move. Is it jerky and glitchy? Smooth and hydraulic?

## 5. Technical Constraints
*   **Platform**: React + Three.js / Canvas.
*   **Theme**: Dark mode required (studio environment).
*   **Responsiveness**: Desktop focus (Large monitors).
